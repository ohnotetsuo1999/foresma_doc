# 要約
営業の仕事は「フェーズを進めること」であり、フェーズは自分たちの行動ではなく顧客の意思決定状況で定義される。初回の案件見極め段階で、投資意欲や導入時期などの本質情報を引き出し、営業が直接対応すべき温度感かどうかを判断する。見極めでストライクゾーンに入らない案件は無理に追わず、インサイドセールスやセミナー案内で育成に回すことが重要。

# 根拠
## フェーズ管理の前提
- フェーズは顧客の意思決定状況の進み具合であり、自社の作業進捗ではない
- 「見積もり提出中」のような行動ベースのフェーズではなく、「価格やスケジュールの合意」など意思決定の合意が基準

## フェーズ一覧（8段階）
1. 案件の見極め
2. ビジネスゴール（および課題）の確認
3. 担当者との価値合意
4. 決裁者との価値合意
5. 最終交渉（価格やスケジュールの合意）
6. 契約手続き
7. 手続き不備（社内用）
8. 受注

## 仕事の定義
- 営業の役割はフェーズを進めること
- フェーズ1の見極めを通過した案件だけが「ストライクゾーン」
- KPIは全商談の打率とストライクゾーンの打率を分けて捉える

# 事例
## 初回ヒアリングでの具体的な聞き方
- 導入時期の質問は「使い始めるとしたら、いつ頃のご予定でしょうか？」と聞く
- 営業側から時期の数字を提示せず、顧客の言葉で時期感を出してもらう

## 投資意欲の見極め
- プロジェクタやモニタの有無など、IT投資意欲の低さが見える兆候は早期に確認する
- 投資意欲が低い場合はSaaS導入可能性が低いと判断できる

## 温度感が低い場合の対応
- 営業が直接対応する温度感でない場合、セミナー案内やインサイドセールスへのプッシュバックでナーチャリングする

# 次にやること
- フェーズ定義を「顧客の意思決定状況」に合わせて見直す
- 初回ヒアリングの質問に「使い始めるとしたら…」の導入時期確認を組み込む
- ストライクゾーンと全商談の成約率を分けてKPI設計する
