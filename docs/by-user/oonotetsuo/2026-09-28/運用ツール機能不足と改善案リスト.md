# 運用ツール（Hubプロトタイプ）機能不足と改善案リスト

## メタ情報
- **タイトル**: 出会えるエージェント 運用ツール（lreach-prototype / lreach_hub）機能不足と改善案リスト
- **目的**: 売上向上・オペレーションコスト削減につながる機能追加の候補を洗い出し、優先度と工数感を揃える
- **対象読者**: 経営・IS責任者・開発担当
- **想定シーン**: 開発ロードマップ検討、外注見積もり前の要件整理
- **タグ**: #送客管理 #着座率 #自動化 #ロードマップ
- **最終更新**: 2026-09-28

---

## 📌 要約
- 送客後（打診 → 日程調整 → 面談日程確定 → 着座）の管理が**すべて手動**。滞留が見えず、企業からの回答を回収する仕組みもない。
- プレ面側は自動割り振り・枠再計算・Slackアラート・再調整フォローが揃っているが、**送客側だけ仕組みが遅れている**。
- 数字（着座率・KGI・見込み売上・ROAS・有効無効判定）は毎日 **CSV書き出し → スキル → シート貼り付け**で回しており、ここの自動化だけでも工数削減が大きい。
- 全36項目。まずやるべきは「送客ステータスの時刻記録と滞留アラート」と、下記「まずやるならこの5つ」。

### 凡例
- **〔売〕** 売上が上がるもの
- **〔効〕** 手作業（オペレーションコスト）が減るもの
- **目安** 開発工数（人日）。コードを読んだうえでのざっくり見積もり。外注なら1人日＝約5〜8万円、社内でClaude Codeを使えばおおむね半分〜2/3。

## 🔍 現状（根拠）

| 領域 | 現状 |
|---|---|
| 送客ステータス | 面談日程調整中／再調整中／確定／着座済／事前・無断キャンセル／お断り／対象外 など。**すべてスタッフが手で切り替え** |
| ステータス履歴 | 変更履歴テーブルに記録されるのは「再調整中」だけ。**いつ確定・いつ着座したかが残らない** |
| 打診 | 送客前に企業へ打診する仕組み・ステータスは**存在しない** |
| 企業側 | 企業が回答・着座報告する画面はない。企業ごとのスプレッドシートとチャット欄のみ |
| 枠管理 | 単価プラン別の月次枠と埋まり率は見られる。企業全体の枠の項目はDBにあるが未使用 |
| 通知 | Slack通知はプレ面関連のみ。**送客関連の通知はなし** |
| リマインド | プレ面は自動送信。送客面談のリマインドは**文面をコピーして手で送る** |
| 数字 | アプリ内にKPIはあるが、IS別着座率・日別推移・ROAS・見込み売上はCSV＋スキルで作成 |
| AI | 通話録音・文字起こし・AI選定理由生成はある。記入や承認は手作業が中心 |
